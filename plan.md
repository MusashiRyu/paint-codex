# Plan: Paint Conversion Web App

**TL;DR**: Build a React web app that lets users search miniature paint colors across three brands (Citadel, Vallejo, Army Painter) and see color-matched alternatives with quality metrics. MVP focuses on search + display with client-side data; **Phase 1.5 refactors the codebase for a clean shipped-app / dev-tools separation before feature work continues**; Phase 2 adds paint lists + Markdown exports with shop links; Phase 3 adds iOS/Android via Capacitor.

---

## **Architecture (target state)**

Core principle: **the shipped app knows nothing about the scraper**. Dev-only utilities, build-time data pipelines, and legacy code live outside `src/` and are excluded from the app's TypeScript project and Vite bundle.

### Top-level layout

```
paco/
├── src/                          # ← SHIPPED APP ONLY (compiled by tsconfig.app.json, bundled by Vite)
│   ├── app/                      #   Root shell: entry, providers, layout, routing
│   │   ├── App.tsx
│   │   ├── main.tsx
│   │   └── providers/            #   Theme provider, store provider
│   ├── features/                 #   Feature slices (Phase 2 growth lives here)
│   │   ├── search/               #   SearchBar, autocomplete hook, search state
│   │   ├── browse/               #   ResultsGrid, PaintCard, BrandFilter
│   │   ├── lists/                #   (Phase 2) paint list CRUD
│   │   └── export/               #   (Phase 2) Markdown + shop link generation
│   ├── shared/                   #   Reusable across features
│   │   ├── ui/                   #   Generic UI primitives (Badge, Pill, Card…)
│   │   ├── hooks/                #   useDarkMode, useDebounce…
│   │   ├── lib/                  #   color math (hexToHSL), delta classification
│   │   └── styles/               #   Global CSS, CSS variables, resets
│   ├── domain/                   #   Domain types + pure business logic
│   │   ├── types.ts              #   Paint, Match interfaces (single source of truth)
│   │   └── paintRepository.ts    #   Loads bundled snapshot only (refresh deferred)
│   ├── data/
│   │   └── paints.snapshot.json  #   Baked-in snapshot (produced by tools/scraper)
│   └── test/                     #   App-side tests, setup.ts
│
├── tools/                        # ← DEV UTILITIES — NEVER SHIPPED
│   └── scraper/
│       ├── scrape.mjs            #   Node CLI: fetches source, writes paints.snapshot.json
│       ├── types.ts              #   Local types (do NOT import from src/)
│       └── README.md             #   How to run the scraper
│
├── scripts/                      # ← Repo-level dev scripts (release, ci helpers)
├── public/                       # ← Static assets served by Vite (icons, etc.)
├── ios/                          # ← Generated by Capacitor (Phase 3)
├── android/                      # ← Generated by Capacitor (Phase 3)
├── capacitor.config.ts
├── vite.config.ts
├── vitest.config.ts
├── tsconfig.json                 #   References tsconfig.app.json + tsconfig.tools.json
├── tsconfig.app.json             #   include: ["src"], excludes tools/
└── tsconfig.tools.json           #   include: ["tools"], separate compilation
```

### Isolation guarantees

1. **`tsconfig.app.json`** has `"include": ["src"]` and `"exclude": ["tools", "scripts", "src/test", "**/*.test.*"]`. The scraper can never be type-checked as part of the app.
2. **`vite.config.ts`** builds only what's reachable from `src/app/main.tsx` via `index.html`. Anything not in that graph cannot enter the bundle.
3. **`tools/` has no import path into `src/`** — enforced by an Oxlint `no-restricted-imports` rule and by not aliasing `@/` into `tools/`.
4. **Types are duplicated on purpose** in `tools/scraper/types.ts` — the scraper is an independent producer; the app is an independent consumer; the JSON file's shape is the contract between them.
5. **`@capacitor/cli` moves to `devDependencies`** (it's a build-time tool, not a runtime dep).
6. **`tailwindcss` is removed** — unused; its presence confuses new contributors.

### Data flow

```
tools/scraper/scrape.mjs ──writes──► src/data/paints.snapshot.json ──import──► domain/paintRepository.ts
                                                   │
                                                   └─► startup: returns bundled snapshot synchronously
```

## **Decisions**

- **Tech**: React 19 + Vite + TypeScript + CSS Modules (colocated with components)
- **Folder structure**: Hybrid — `src/features/*` for feature slices, `src/shared/*` for reusable UI/hooks/lib, `src/domain/*` for types + business logic, `src/app/*` for the shell
- **Scraper isolation**: Lives in top-level `tools/scraper/`, excluded from `tsconfig.app.json` and Vite build, lint rule blocks cross-imports. **Never ships.**
- **Data delivery**: Bundled snapshot (`paints.snapshot.json`) only for now. Runtime refresh is explicitly deferred.
- **State management**: Zustand + `persist` middleware for Phase 2 (paint lists in localStorage).
- **Search**: Fuse.js fuzzy matching (threshold 0.3) + autocomplete
- **Styling**: Plain CSS Modules with `prefers-color-scheme` dark mode; **Tailwind removed** (unused).
- **Mobile**: Capacitor. App ID `com.musashi.paco`, display name `Paco`.
- **Export** (Phase 2): Markdown format with vliegeruit.com links
- **Types contract**: Scraper duplicates its own types; the JSON snapshot's shape is the interface between producer and consumer.
- **Excludes now**: User auth, backend, native-only features (Phase 3)
