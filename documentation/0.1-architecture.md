# Architecture

## Component Table

| Component | Path | Responsibility | Notes |
| --- | --- | --- | --- |
| App shell | `src/app/App.tsx` | Card/viewport layout, which of the two screens is showing, FAB, header About action, overlay state (search sheet, new list sheet, about sheet), export trigger, list rename wiring, and the Color Lab's add-to-list. | **Two screens, no router.** `screen` is `'lists' | 'collab'` in `useState`; the header subtitle, the FAB and the panel all follow it. The FAB renders on the List screen only — it adds to the list being shown, and Collab shows none. `handleLabAdd` adds the paint and flashes `Added to <list name>`, because the Lab never shows a list and a bare tick would not say where the paint went; it ignores what `addPaintToList` returns, since a card only offers its button when the paint is not listed and the duplicate case is a double-tap race. `onAddPaint` is withheld entirely when there are no lists, so the cards render no button rather than a dead one. Lists-first redesign; previous browse/search/filter wiring removed. Registers all three sheets with `useBackDismiss`. Passes `onExportList` only when the `markdownExport` flag is on. The search sheet opens two ways, and which one is App's state: `focusPaintId` is `null` for the FAB's blank search and a paint id when a list row was tapped. `openSearch(paintId)` takes a **required** argument — `onOpenSearch` and the FAB's `onClick` are wired straight onto DOM handlers, so a defaulted parameter would type-check and then receive the SyntheticEvent as a paint id. `closeSearch` clears it, or the next FAB press re-opens on the last row tapped. |
| Feature flags and links | `src/app/config.ts` | `appConfig.featureFlags` (compile-time toggles), `appConfig.links` (every URL the app can send someone to), and `APP_VERSION`. | `markdownExport: false` — the export download action is off for now. `supportLink: true` — it toggles the About sheet's support section. `APP_VERSION` is the web-only fallback for the version display and is pinned to `android/app/build.gradle` by `src/test/appVersion.test.ts`, which pins the two iOS build settings to it as well — `versionName` and `versionCode` are the only version values anyone edits. |
| App styles | `src/app/App.module.css` | Viewport dark-background, centered card, header, divider, FAB styling. | Card is full-screen on mobile; centered 390px card on desktop ≥500px. |
| Store | `src/app/providers/store.ts` | Persisted Zustand store; manages lists, selected list, and paint membership. | A list holds `paintIds: string[]`, never Paint objects — see the conventions below. `PaintList` also carries `icon` and `color`. Persist is at version 4; `migrate` is cumulative, so a version 0 store picks up every step in one pass. v3 and v4 both rewrite paint ids through `src/data/paintIdMigration.json` — the id scheme changed twice, and the map is built to be safe to apply more than once. |
| Paint repository | `src/domain/paintRepository.ts` | Holds the live catalog and publishes replacements: `getPaints`, `subscribeToPaints`, `setPaints`, `getPaintIndex`, `getBrowseOrder`, `getBrowsePosition`, `getLabIndex`, `findNearestPaint`, `resolvePaints`. | Seeded synchronously at import from the runtime cache, falling back to the bundled snapshot, so there is never a paintless first render. `resolvePaints` turns stored ids into catalog entries and drops ids that no longer exist, since a refresh can retire a paint. The id index and the browse order are both memoised against the array they were built from, so replacing the catalog invalidates them automatically — an order held against the old array would put the browse view at paints that have left it. `getLabIndex` is the catalog in CIELAB as a flat `Float64Array`, on the same contract, and `findNearestPaint` scans it for the paint closest to an arbitrary color. That is the Color Lab's bridge back to reality: a mixed or derived color is not a paint, so it has no precomputed `matches` and needs a live scan. CIE76 in the Lab of `hexToLab`, the Lab the snapshot's own deltas were measured in. Unlike `getTopMatches` it excludes no brand — equivalents answer "what do I buy instead of this Citadel paint", this answers "what is closest to this color", where every paint is a candidate. |
| Catalog parser | `src/domain/paintCatalogSource.ts` | `PAINT_CATALOG_SOURCES` plus `parsePaintCatalog(documents)`: reads one markdown table per brand, merges rows that are one color under several range names, assigns range-qualified ids, and computes every paint's cross-brand equivalents in CIELAB. | The one parser, shared by the build-time scraper and the runtime refresh — see the conventions below. Pure string and arithmetic work, no DOM, so Node can run it too. Columns are located by heading rather than position, because Citadel's table has no `Code` column and the other two do. Validates as it goes: colors normalize to `#RRGGBB` or the entry is dropped, and a row whose range upstream left null is dropped. |
| Catalog refresh | `src/domain/paintCatalogSync.ts` | `refreshPaintCatalog()` — fetch all three brand documents, validate, adopt. Returns `updated` / `unchanged` / `rejected` / `failed`; never rejects. | Fired once per launch from `main.tsx`, at idle, unawaited. One `AbortController` covers the whole round, so the deadline is the round's rather than resetting per brand, and a partial fetch fails outright. Skips parsing when the combined hash is unchanged, and skips the render when changed documents parse to the same paints. `findShortfall` rejects a parse under half the bundled count in total *or* in any single brand. |
| Catalog cache | `src/domain/paintCatalogCache.ts` | localStorage persistence of a refreshed catalog under `paco-paint-catalog`. | Stores a signature of the snapshot the writing build shipped; a mismatch drops the cache, so releasing a corrected snapshot actually reaches users who cached a bad one. Anything unreadable is discarded, never repaired. Storage failures cost persistence, not the session. |
| Catalog hook | `src/app/providers/usePaintCatalog.ts` | `useSyncExternalStore` binding from the repository to React. | The only place React meets the catalog, which is what keeps `domain/` React-free. |
| String hash | `src/shared/lib/hash.ts` | `hashString` — FNV-1a, 32-bit. | Change detection only. Lets us ask "same documents as last time?" without keeping 270 KB around to diff. |
| List icon | `src/shared/ui/ListIconSvg.tsx` | Renders one of 8 SVG emblems (skull/star/shield/wing/crown/flame/moon/drop) for list tabs. | Pure presentational component. |
| Sheet | `src/shared/ui/Sheet.tsx` / `Sheet.module.css` | Bottom sheet: backdrop, rounded lip, header with close action. `size="auto"` sizes to content, `size="tall"` is a fixed-height flex column whose body scrolls. | Owns the dismissal and focus contract so a caller cannot wire half of it: Escape, focus trap, `role="dialog"`, `aria-modal`, `tabIndex={-1}`. `useBackDismiss` stays with the caller because the open flag does. Replaced 43 byte-identical lines duplicated across the two overlays. |
| Pill | `src/shared/ui/Pill.tsx` / `Pill.module.css` | Interactive chip: list tabs, brand filters, the dashed "+ New" slot. | Always a button — every pill selects something. `style` is the escape hatch for a tab tinted with a list's user-chosen color, which cannot come from a token. |
| Badge | `src/shared/ui/Badge.tsx` / `Badge.module.css` | Static status label: the IN LIST badge and the ΔE delta pill. | Never interactive; anything clickable is a `Pill`. `block` is the full-width centered variant under an equivalent tile; `compact` is the tile-sized one, on the same 11px and the same 3px lead as `block` so the IN LIST badge at a tile's head stands exactly as tall as the delta pill at its foot. The delta pill's color arrives via `style` from `shared/lib/color.ts`. The IN LIST badge is one badge in two places — the result row and the equivalent tile — because it reports one fact, list membership, about whichever paint it sits on. |
| IconButton | `src/shared/ui/IconButton.tsx` / `IconButton.module.css` | Round outline-only icon button — header actions and the inline remove. | Requires `label`, which sets both the accessible name and the tooltip, because these buttons never have visible text. `danger` is outline-only on purpose so a delete cannot out-weigh the gold action beside it. |
| GoldButton | `src/shared/ui/GoldButton.tsx` / `GoldButton.module.css` | The filled gold gradient action: the FAB (`lg`) and the add button (`md`). | The app's only solid fill, and deliberately only two instances — a third stops it reading as *the* action. Positioning is the caller's via `className`; the button owns only its look. |
| GhostButton | `src/shared/ui/GhostButton.tsx` / `GhostButton.module.css` | Outlined pill action with a text label — the workhorse button. | `quiet` drops the fill for an offer rather than an urged action. Replaced the ad-hoc `addFirstBtn` / `createBtn` / `browseBtn`; CREATE LIST now uses native `disabled` instead of `pointerEvents: none`. Given `href` it renders an `<a>` instead — a union type, because a control that leaves the app has nothing to disable and no handler to run. The stylesheet states `display`, `text-align` and `text-decoration` so the two renderings are identical rather than nearly so. |
| ExternalLink | `src/shared/ui/ExternalLink.tsx` / `ExternalLink.module.css` | The inline text link out of the app. | The only anchor style there is: Paco has no internal navigation, so every link in it is a handoff to the browser. Color comes from the global `a` rule; only the underline offset is local. |
| Outbound link contract | `src/shared/lib/externalLink.ts` | `EXTERNAL_LINK_PROPS` — the `target`/`rel` pair every outbound link carries. | `target="_blank"` is what makes Capacitor's WebView hand the URL to the system browser; without it the page loads *inside* the app and replaces the UI. `noreferrer` is what makes the privacy policy's "the destination is not told where you came from" true. One constant so that if a device ever fails to hand off and `@capacitor/browser` is needed, one file changes. |
| Action icon spec | `src/shared/ui/actionIcon.ts` | `ACTION_ICON` — shared geometry for the stroked line glyphs. | Was local to `ListsPanel` until the header About button needed the same 24px grid and stroke weight. An icon that sets its own stroke or fill is a bug. |
| TextField | `src/shared/ui/TextField.tsx` / `TextField.module.css` | Text input: `pill` is the standing sheet input, `inline` is edit-in-place. | Spreads the remaining native input props, because the blur/keydown handling an edit-in-place rename needs belongs to the caller. |
| Swatch | `src/shared/ui/Swatch.tsx` / `Swatch.module.css` | A block of color with an inset dark ring. | The ring is inset so it sits inside the radius — a swatch must read as the paint, not as a bordered box. `as="span"` for swatches inside a button, which may only hold phrasing content. Four sizes: `sm` in a list row, `md` in a result row, `tile` — a `--control-lg` square — at the head of an equivalent tile, where the rest of the row belongs to the IN LIST badge, and `wide` across a Color Lab slot, the only one that is not square. |
| Paint summary | `src/shared/ui/PaintSummary.tsx` / `PaintSummary.module.css` | One paint, named and described: swatch, name, brand, range · hex, with the trailing action left to the caller as a slot. Given `onSelect`, the swatch and text become one button and the slot's children sit *beside* it. | Lifted out of `ResultCard` when the Color Lab needed the same row without the equivalents grid. The trailing area is `children` because "what you can do with this paint" is the only thing that differs between the surfaces showing one. Spans throughout whether or not it is a button, so there is one render path rather than two kept looking alike — a button may only hold phrasing content, and the layout comes from `display` in the stylesheet. Every class name survived the move: the tests and `check-layout.mjs` select on `[class*="paintName"]`, and `cardMetrics.ts` still measures `.paintRow`'s height from another feature's folder. |
| Section heading | `src/shared/ui/SectionHeading.tsx` / `SectionHeading.module.css` | The gold Cinzel rule that divides a scrolling surface into named groups. | Was `ListsPanel`'s `.sectionType` until the Color Lab wanted it five more times — the mix preview, the color theory block, its three derived colors, and each list in the picker. |
| Lists panel | `src/features/lists/ListsPanel.tsx` / `ListsPanel.module.css` | Tab bar (list selection + "+ New") and scrollable content (paints grouped by category, empty state, list header actions), plus inline list rename. | Each row reports its paint back through `onShowEquivalents(paintId)`, mirroring `onRemovePaint`: ids, not objects. Pencil action renames the list: swaps the header name for an input. Enter/blur commits, Escape or back cancels, switching tabs cancels. The header is gated on the list existing, not on it having paints, so an empty list can still be renamed and deleted. Delete is always available — deleting the last list is allowed and drops to the "No lists yet" state. Category headings are `SectionHeading` since the Color Lab wanted the same rule five more times. Unmounted while Collab is showing, so the rename draft and the scroll reset like a screen's should. |
| Bottom nav | `src/app/BottomNav.tsx` / `BottomNav.module.css` | The two top-level destinations: **List** and **Collab**. | Lives in `app/` and takes no items — it names this app's two screens, so it is shell rather than a primitive, and is absent from the barrel. It is also the new owner of the home-indicator inset: the bar is the lowest thing on screen, so it pads itself and everything above it clears the *bar* (`--nav-height`) rather than the inset. Its background is opaque, and has to be: the design's mock draws it at 0.94 over a flat ground, and over the card's background image 6% is enough for a paint name scrolling underneath to read straight through and compete with the labels. |
| Color Lab | `src/features/lab/ColorLab.tsx` / `ColorLab.module.css` | The Collab screen: the Mixing/Matching tabs, the three paint slots, and the picker. | Slots hold paint **ids**, not paints, on the store's reasoning — the background refresh can replace the catalog mid-session and a held `Paint` would go on showing a color that had left it. Each tab keeps its own slots: they answer different questions, so switching must neither carry nor clear. Registers the picker with `useBackDismiss`. |
| Paint slot | `src/features/lab/PaintSlot.tsx` / `PaintSlot.module.css` | An empty invitation or a filled card, in a `stacked` or `row` variant. | Filled, the swatch stays a button: re-picking is the common correction, and making someone clear first would be two taps for one decision. The clear action is separate and small, over the corner — the row variant has no spare line for it. |
| Nearest paint card | `src/features/lab/NearestPaintCard.tsx` / `NearestPaintCard.module.css` | A computed color, and the real paint you would reach for instead: `SectionHeading` + the derived swatch + a `PaintSummary` carrying the ΔE and the add/IN LIST pair. | Used by both tabs, which is what makes them read as one screen. The computed swatch comes first because it is the answer to what was asked; the card under it is what makes the answer actionable. The ΔE is shown even when it is large — a derived color has no reason to have a near neighbour, and saying "the closest thing is not very close" beats implying a match. Classified through `shared/lib/color.ts` like every other delta; no new thresholds. |
| Mix panel | `src/features/lab/MixPanel.tsx` / `MixPanel.module.css` | The two slots, the six-block blend strip, and a card per step. | The strip carries only a percentage and a hex: six blocks across a 320px card is 46px a column, and a paint name does not fit in 46px, so the names go in the cards below. Only the four **intermediate** steps get a card — 0% and 100% are the paints in the slots above, whose nearest paint is themselves. |
| Match panel | `src/features/lab/MatchPanel.tsx` / `MatchPanel.module.css` | The base slot and the three derived colors under a `COLOR THEORY` heading. | One `NearestPaintCard` per derived color, each under its own sub-heading — Complementary, Highlight, Shade. |
| Paint picker sheet | `src/features/lab/PaintPickerSheet.tsx` / `PaintPickerSheet.module.css` | Choosing a paint for a Color Lab slot: **My Lists** or **Search Catalog**. | Search Catalog is `PaintSearch` itself, not a lookalike, so the Lab gets Fuse ranking, color-ordered browse and windowing over all 2,279 paints — and gets them again whenever the search improves. Mounted with no `listedPaintIds`, so every card offers its button: membership is the wrong fact when the question is which paint goes in the slot, and an IN LIST badge where the button should be reads as a control taken away. My Lists is the other half and the reason the picker is not simply the search sheet — it is the fastest path to a paint you own, which is most of what anyone mixes. A list with nothing resolvable in it is left out rather than shown as a heading over nothing. |
| Paint item | `src/features/lists/PaintItem.tsx` / `PaintItem.module.css` | Single paint row in the list view: a button holding swatch, name, brand/type and hex, plus a remove button beside it. | The "×" remove button is always visible; the old `editMode` prop and left "–" button were removed as redundant. The row is a button that opens the paint's equivalents, and remove is its **sibling**, not its child: a button may not nest one, and the action with no undo must not be what a stray tap on the row hits. Its label is `Show equivalents for <name> by <brand>` and deliberately does not begin with "Go to" — that prefix is how `tools/layout/check-layout.mjs` picks equivalent tiles out of a page. Inner elements are spans (phrasing content) with `display: block` restored, or the name loses its ellipsis. `.item` keeps the border and padding, so the row looks exactly as it did before it became tappable. |
| Back dismiss hook | `src/shared/hooks/useBackDismiss.ts` | LIFO stack of dismissable layers; routes the Android back gesture to the topmost open layer and only exits the app when none remain. | Requires the `@capacitor/app` plugin — Capacitor core has no back handling, so back would otherwise finish the activity. No-op on web. |
| Escape dismiss hook | `src/shared/hooks/useDismissOnEscape.ts` | Closes the layer on Escape; desktop counterpart to `useBackDismiss`. | Only mounted layers listen and the handler stops propagation, so nested layers close innermost-first. |
| Focus trap hook | `src/shared/hooks/useFocusTrap.ts` | Holds keyboard focus inside an overlay and returns it to the trigger on close. Returns a ref for the container, which needs `tabIndex={-1}`. | `aria-modal` describes a layer as modal without making it behave that way. The trigger is captured during render, not in an effect — React applies `autoFocus` while committing, so an effect would capture the input instead. Visibility filtering is attribute-based on purpose: `offsetParent` reports nothing for `position: fixed` sheets and nothing at all under jsdom. |
| Search sheet | `src/features/search/SearchSheet.tsx` | `Sheet` chrome around `PaintSearch`, for the List screen. | Thin by design. Everything that makes the search work moved to `PaintSearch`, so the Color Lab's picker could hold the same component under a different header; what is left here is the title and `action="add"`. |
| Paint search | `src/features/search/PaintSearch.tsx` / `PaintSearch.module.css` | The catalog itself: text input, brand filter chips, and a windowed list of result cards. | Renders a **fragment**, not a wrapper — `flex: 1` on the results has to resolve against whichever `Sheet` is holding it. `action` is `add` or `select`, and `select` changes what a card *is*: the whole summary row becomes the button, the gold `+` goes (two adjacent tab stops calling one handler is noise), and an equivalent tile selects the paint it names instead of jumping the list to it. Jumping is browsing, which is the right verb when filling a list and the wrong one when filling a slot. Uses `search.ts` Fuse.js logic; opened by FAB, by "+ ADD FIRST PAINT", or by a paint's row in the list. `role="dialog"` + `aria-modal`. **Two modes, one list.** With a query it is a search, ranked by Fuse relevance. Without one it is a browse: the whole catalog in perceptual color order from `getBrowseOrder`, so the cards above and below a paint are the colors nearest to it — which is what a paint with no close equivalent is answered with. `focusPaintId` opens that browse anchored on one paint: query empty, brand filter on All, that card ringed, scrolled to and focused. Narrowing to the paint's own brand is exactly what would hide the cross-brand neighbours the user opened it to see, which is why the anchor is a *position* and not a search. Seeded with `useState` initializers, never an effect: `paintCatalog` changes identity on the background refresh, and an effect keyed on it would wipe a half-typed query and re-anchor away from wherever the user had scrolled. `autoFocus` is suppressed for that open, or the soft keyboard covers the colors the user came to compare. An equivalent tile **moves the list** to the paint it names — clearing the query and any brand filter, because those are the two things that can hide what sits next to it. The `Tab` handler on the scroller widens the window before the browser picks the next tab stop; without it the focus trap wraps at the edge of the window instead of walking into the next card. |
| Result card | `src/features/search/ResultCard.tsx` / `ResultCard.module.css` | One paint in the results list, with its cross-brand equivalents. | The summary row is `PaintSummary`; this composes it with the equivalents grid under it. Lifted out of the sheet's `.map` when the list became windowed, and memoised — that is why it is a component. A scroll re-renders the sheet several times a second; without the memo every mounted card re-renders and re-sorts its matches on each one. The memo only holds while every prop is stable, which is what the `useCallback`s on `onAdd`, `onJump` and `registerCard` are for. Carries `role="listitem"` with `aria-posinset`/`aria-setsize`, so a screen reader is told the size of the catalog rather than the size of the window. |
| Card metrics | `src/features/search/cardMetrics.ts` | `estimateCardHeight` and `visibleTileCount`: what a card will be tall before it is laid out. | The windowed list has to give a height to cards it has not mounted. Card height is variable but not unpredictable: what dominates it is the tile count, and that is countable from the data with no layout at all. Tile-count aware the estimate is out by about a wrapped line; a single constant would be out by 380px, which is the difference between a scroll that feels like a list and one that lurches. The numbers are the sums of the CSS they stand for, written out so a stylesheet change has an obvious number to change here. |
| Windowed list | `src/features/search/useWindowedList.ts` | Mounts only the cards on screen and gives the rest to two spacers. | The catalog is 2,279 paints at ~37 elements each: rendered whole that is ~84,000 elements and 8,722 focusable buttons, which the focus trap re-queries on every Tab. Hand-rolled rather than a library, because both store listings answer their privacy forms with "four runtime dependencies". Offsets are a prefix scan over measured-or-estimated heights, rebuilt during render so no frame paints with stale spacers. Measurement is one layout effect per commit, keyed by paint id so it survives a re-sort or a catalog refresh; a width change clears every measurement, because the column count and so every height changes with it. The anchor scroll waits both for a pass that measures nothing new *and* for the re-render it asked for to have landed — anchoring against estimates taken at the fallback width put the card a third of the catalog away, and anchoring against a stale DOM did it again under StrictMode. Those are two different conditions and the first alone is not enough. **A programmatic scroll is a request, not a result.** Writing `scrollTop` is clamped to the scroll extent the engine currently believes in, and on a scroller nearly a million pixels tall that belief lags the spacers already in the DOM — so the landing is read back (the position updates synchronously; only the event is deferred), retried across a few commits, and the range is derived from wherever the scroller actually is either way. Assuming the write landed is what left an empty sheet on iOS. For the same reason **every** scroll event counts, including the hook's own: a flag that swallowed them threw away the one correction that catches the difference, and latched forever when a write moved nothing. Moving the window is always safe — the top spacer is `offsets[start]`, so every card keeps its absolute position whichever of them are mounted. Under `WINDOW_BYPASS_BELOW` results it renders everything and both spacers are 0. |

## Conventions

- **TypeScript is strict everywhere.** Every project (`app`, `test`, `node`, `tools`) sets `strict: true`. Test files are typechecked by `tsconfig.test.json`; they were excluded from every project until retro 005.
- **Delta classification goes through `shared/lib/color.ts`.** Never inline a threshold in a component.
- **A raw value may appear in a component stylesheet only if it is used exactly once.** The moment the same color or number turns up in a second file it belongs in `shared/styles/tokens.css` under a name. This is written down because it was already broken: 50 raw color literals across five modules, including `#dcb877` pasted three times while `--gold-title` sat defined and unused, and four grays hand-picked within 7 per channel of tokens that already existed. Full system in [0.2-design-system.md](0.2-design-system.md).
- **Chrome lives in `shared/ui/`, never in a feature.** A sheet, pill, badge, icon button, gold button, ghost button, text field or swatch comes from the primitive. A feature stylesheet is for what is genuinely specific to that screen — a result card, a section heading, a grid. The rule exists because it was broken: two overlays carried 43 byte-identical lines of sheet chrome, and the same button was written four ways.
- **Every outbound link goes through `EXTERNAL_LINK_PROPS`.** Never hand-type `target`/`rel` on an anchor. `target="_blank"` is load-bearing rather than cosmetic — it is the mechanism by which the Android WebView hands a URL to the system browser, and without it the link navigates the app away from itself with no way back. `AboutSheet.test.tsx` asserts the pair on *every* link it renders, not on a chosen one.
- **Overlays are a `Sheet`, not a hand-built dialog.** `Sheet` owns Escape, the focus trap and the dialog roles together, so the three cannot be wired one-and-a-half times. Only `useBackDismiss` stays with the caller, since the open flag does.
- **Cinzel labels, EB Garamond reads.** Every title, tab, chip and button is `--font-display` with tracking; body copy, inputs and prose empty states are `--font-body`. A control set in Garamond, or a sentence set in Cinzel, is a bug.
- **Never render `paint.matches` directly** — it stores ids and deltas, not paints. Go through `getTopMatches`, which sorts, caps and resolves, and which drops an id whose paint has left the catalog instead of rendering a tile that jumps nowhere.
- **Overlays wire up all three**: `useBackDismiss` (Android), `useDismissOnEscape` (desktop) and `useFocusTrap`, and carry `role="dialog"`, `aria-modal` and `tabIndex={-1}`. The first two make it dismissable, the third keeps a keyboard user inside it.
- **Two screens, and still no router.** `App` holds `screen` in `useState` and renders one panel or the other. Adding a third destination is a third value and a third `BottomNav` entry, not a routing library — nothing here has a URL, a back stack of screens, or a deep link to honour, and the Android back gesture is already spoken for by `useBackDismiss`, which pops overlays and then exits.
- **The nav bar owns the bottom inset.** It is the lowest thing on screen, so it pads itself with `--inset-bottom` and everything above it clears the *bar* — `calc(… + var(--nav-height) + var(--inset-bottom))`. Spending the inset twice lifts the FAB an inset higher than it needs on exactly the phones with least room.
- **A computed color is answered with a real paint.** Anything the Color Lab derives goes through `findNearestPaint` before it is offered, and only catalog paints are ever added to a list. Lists hold catalog ids; a swatch you cannot buy is not a list entry.
- **A ΔE is a ΔE.** Every delta in the app is CIE76 in the Lab of `hexToLab`, and is classified through `shared/lib/color.ts`. The Color Lab's numbers sit next to the snapshot's own in the same UI, so they have to be measured the same way — the design's mock used RGB distance with thresholds of 40 and 90, and adopting that would have made the same word mean two things on two screens.
- **Open work lives in `documentation/OPEN-ITEMS.md`**, not in per-retro deferred sections. A retro records what a session did; anything left undone goes on that one list and is deleted from it when closed.
- **One parser for the catalog.** `parsePaintCatalog` in `domain/paintCatalogSource.ts` is the only code that reads upstream markup; `tools/scraper/scrape.mjs` and `checkUpstream.mjs` import it rather than carrying a copy. Two parsers would let a bundled snapshot and a refreshed one disagree about the same documents. Node loads that module through type stripping, so it must stay free of non-erasable syntax and of value imports from `src/` — which is why the CIELAB conversion sits inside it rather than in `shared/lib/color.ts`.
- **The catalog is read through `getPaints()`, never imported.** `src/data/paints.snapshot.json` is the floor, not the source of truth — importing it directly pins a component to build-time data and it will miss the runtime refresh.
- **The refresh is silent.** No spinner, no toast, no error surface. Being offline is the normal case; the app is fully usable on the cached or bundled catalog and simply shows better data if the fetch lands.
- **Lists persist paint ids, never Paint objects.** Resolve with `resolvePaints` at read time. Storing copies means a catalog refresh never reaches saved lists. Any change to the persisted shape needs a `version` bump and a cumulative `migrate` branch — and so does a change to the *id scheme*, since `resolvePaints` drops what it cannot find and an unmigrated list empties itself with no message.
- **The catalog refresh is the app's only network traffic.** It is three requests now rather than one, but to a single host and for a single purpose; anything user-visible about that count belongs in `store/privacy-policy.md`, which enumerates the URLs. Everything else — fonts, imagery, the snapshot it launches on — ships in the bundle, and the app is fully usable with the radio off. Adding a request for a *different* purpose needs a reason as good as this one's: the refresh exists because paint data goes stale between releases, and it degrades to "no change" rather than to a broken screen. A webfont or an analytics beacon does not clear that bar.
- **Tests run through the app's own Vite.** `vitest.config.ts` merges
  `vite.config.ts` rather than restating it, and Vitest is kept on a major that
  accepts the project's Vite as a peer instead of installing its own. Both rules
  exist because they were broken: the configs had drifted on the `@` alias, and
  Vitest 2 hard-depended on Vite 5 while the build used Vite 8 — so the suite
  was transforming and resolving code with a toolchain three majors from the one
  that ships. A green test run means less than it looks like when that is true.
- **Store assets are generated, never hand-exported.** Icons, splashes,
  screenshots and the feature graphic all come from `npm run` scripts over a
  single source. Hand-exporting is how a listing ends up showing last year's UI
  and an icon that is right in four density buckets out of five — the drift is
  invisible because nobody looks at their own listing.
- **Upstream is untrusted input.** It is a scraped third-party document, so `parsePaintCatalog` validates rather than assumes: colors are normalized to `#RRGGBB` or the entry is dropped, a row whose range is null is dropped, and `paintCatalogSync` rejects a parse yielding under half the bundled paint count in total or in any one brand. Loosening any of those puts unrenderable data straight into the UI.

## Paint catalog

Upstream is `Arcturus5404/miniature-paints` (MIT), one markdown table per brand
served raw from GitHub. Paco reads three of them — `Citadel_Color.md`,
`Vallejo.md`, `Army_Painter.md` — listed with their app-facing brand labels in
`PAINT_CATALOG_SOURCES`. They reach the app twice.

**At build time.** `npm run scrape` fetches all three, runs
`parsePaintCatalog`, and writes `src/data/paints.snapshot.json` minified. That
snapshot ships in the bundle and is what a freshly installed app shows.

**At launch.** `main.tsx` calls `refreshPaintCatalog()` once, at idle and
unawaited. It fetches the same three documents with `cache: 'no-cache'`, so the
launch really does check rather than trusting the five-minute `max-age`; an
unchanged upstream answers `304` with an empty body, which is why checking
every launch is affordable. All three or none: a partial fetch would parse
cleanly and replace a complete cache with one quietly missing a brand. If
anything changed, the set is parsed, sanity-checked, written to localStorage,
and published to subscribers — the UI re-renders with the new paints underneath
the user.

Reads stay synchronous throughout: the repository resolves cache-then-bundled
at import, so nothing ever waits on the network.

| Layer | Wins over | Where |
| --- | --- | --- |
| Refreshed this session | everything | memory, via `setPaints` |
| Cached from a past session | bundled | `localStorage['paco-paint-catalog']` |
| Bundled snapshot | — | `src/data/paints.snapshot.json` |

Four things keep a bad upstream from becoming a bad app: a parse yielding under
half the bundled paint count is rejected outright, so is one where any single
brand falls under half of what it shipped, a cache written by a build with a
different snapshot is discarded, and a cache that fails to validate is thrown
away rather than repaired. In every one of those cases the app falls back to
data it shipped with. The per-brand floor is not redundant with the total: the
realistic failure now is one file being renamed while the other two answer
normally, and Citadel is small enough that losing it whole still leaves the sum
well over half.

Cross-origin works because `raw.githubusercontent.com` answers
`Access-Control-Allow-Origin: *`, and the request sets no author headers, so it
takes no CORS preflight. Android needs `android.permission.INTERNET`, which the
manifest already declares.

### Paint ids

An id is brand + primary range + name — `citadel-base-abaddon-black`. The
range is in there because it has to be: upstream carries the same name in more
than one range at *different colors*, and Citadel's Administratum Grey really
is a different gray in Layer and in Air. The product code is deliberately not
in the id, even though it would be shorter and unique, because upstream leaves
it null for whole ranges and fills some in later — an id that changes when a
spreadsheet cell is filled in would silently empty every list referencing it.

Three things reduce the raw rows to entries:

1. **Rows identical in range, name and color** are the same paint listed
   twice, and collapse.
2. **One color under several range names** — Citadel's Abaddon Black as both
   Air and Base at `#000000` — merges into one entry whose `category` lists
   every range, primary first: `Base · Air`. On screen those rows were the same
   name, the same swatch and the same hex, so keeping them apart only ever
   produced duplicate search results and duplicate equivalent tiles. The ranges
   are all still recorded, so nothing is lost against upstream.
3. **What still clashes** — 17 rows sharing a name and primary range at
   different colors, Vallejo reissues under two product codes mostly — is
   ordered by code then color and suffixed `-2`, `-3`. Ordering by the row's
   own content rather than its position keeps the suffixes from shuffling when
   upstream re-sorts.

"Primary range" is brush before airbrush, then alphabetical. Brush leads
because it is what someone browsing a color usually wants, and because it is
what the pre-Arcturus catalog contained, so carried-over lists land on it.

`src/data/paintIdMigration.json` carries saved lists across both id changes —
the move to range-qualified ids, and the range merge that followed. The store
applies the same map at v2 → v3 and v3 → v4; `buildIdMigration.mjs` refuses to
write a map containing an entry whose target is itself a key, which is what
makes applying it twice safe. Twenty legacy paints have no entry because the
new source does not carry them; those drop out at resolve time, as any retired
paint does. Mapping them to the nearest color instead would have put a
different product in someone's list under the old name.

### Equivalents

Upstream ships color, not conversions, so the equivalents are ours.
`attachMatches` converts every paint to CIELAB and keeps each one's six nearest
neighbours *from other brands* — the nearest Citadel paint answers a different
question than "what do I buy instead of this Citadel paint".

The metric is CIE76, plain Euclidean distance in CIELAB, because that is the
scale the thresholds in `shared/lib/color.ts` are already expressed on: 3 for
"indistinguishable", 7 for "still usable". CIEDE2000 models perception better
but returns systematically smaller numbers, so adopting it would silently
reclassify every match in the app without either constant changing.

Six is stored because six is what `SearchSheet` renders. The snapshot ships in
the bundle *and* is mirrored into localStorage, so every extra match is paid
for three times.
