# Design System

The visual language of the app, extracted from the stylesheets rather than
invented ahead of them. Every token below replaced values that had already been
written out by hand two to seven times.

**The design itself is by [Lukas Stordeur](https://github.com/LukasStordeur).**
The gold palette, the Cinzel/EB Garamond pairing, the card-on-texture layout and
the grimoire voice are all from the original Paint Codex design; retro 003
rebuilt the app around it. Nothing in this document is a new design decision —
it names decisions that were already made, so the code stops re-deriving them by
hand. Where a value below reads as arbitrary, assume it is deliberate and check
the design before changing it.

Source of truth: [`src/shared/styles/tokens.css`](../src/shared/styles/tokens.css).
Nothing else defines a colour, radius, type size, tracking or shadow.

## The rule

> A raw value may appear in a component stylesheet only if it is used **exactly
> once**. The moment the same number or colour turns up in a second file, it
> belongs in `tokens.css` under a name.

That rule is what the extraction enforced, and it is the only thing that keeps
the file from rotting back into literals. Before it, the codebase carried 50
raw colour literals across five modules and two components — including
`#dcb877` pasted three times while `--gold-title` sat defined and unused.

## Voice

Dark, gilt and bookish: a grimoire, not a utility. Three decisions carry it,
and each of them is load-bearing rather than decorative.

**Two faces, two jobs.** Cinzel is an inscriptional capital — it takes every
title, label, tab, chip and button, always with tracking, and never sets a
sentence. EB Garamond takes everything meant to be *read*: body copy, inputs,
and the italic empty states. A control that is Garamond, or a paragraph that is
Cinzel, is a bug.

**Gold is the only accent.** There is one chromatic axis in the entire app.
Nothing is blue, nothing is branded a second colour, and the only gradient is
the primary action. Status colour is the sole exception, and it is confined to
ΔE match quality.

**Nothing is filled.** Controls are outline-and-tint. The gold gradient appears
exactly twice — the FAB and the add button — and is the app's only solid
foreground. Destructive actions get an outline and a muted red, deliberately
quieter than the gold primary next to them, so a delete never out-weighs the
action beside it.

That count is a budget, and it is already spent. The About sheet's support
action is the case that tested it: it could have argued for the loudest
control in the app, and it got a `GhostButton` instead. Two reasons, and the
second is the real one. `GoldButton` is round and icon-only, so a text label
was never going to fit it — and the About sheet is an informational surface,
not an action's home screen. A third gold gradient would also have stopped
the first two meaning anything.

## Colour

### Gold — the brand axis

| Token | Value | Role |
| --- | --- | --- |
| `--gold` | `#c9a86a` | The base mark: links, rules, active borders |
| `--gold-bright` | `#e4c98a` | Selected/active foreground, gradient highlight |
| `--gold-title` | `#dcb877` | Titles only |
| `--gold-deep` | `#b3903f` | Gradient shadow end |
| `--gold-pale` | `#c9b898` | Desaturated heading, empty states |
| `--on-gold` | `#1c1610` | The only foreground allowed on a gold fill |

Gold at partial alpha does three different jobs, and the tokens keep them
apart. Fills tint a surface, hairlines divide content, borders bound a control:

| Token | Alpha | Job |
| --- | --- | --- |
| `--gold-fill` | 0.12 | Resting tinted surface |
| `--gold-fill-strong` | 0.16 | Selected tinted surface |
| `--gold-line` | 0.15 | Section rules, sheet lip, card hairlines |
| `--gold-border` | 0.25 | Input and ghost-button edges |
| `--gold-border-strong` | 0.40 | The dashed "+ New" tab |
| `--gold-inset` | 0.14 | The desktop card's 1px inner ring |

Nine hand-written alphas between 0.10 and 0.40 collapsed into these six.

### Text — five steps

`--text-primary` `#ece4d2` → `--text-secondary` `#ab9f8c` →
`--text-muted` `#9c9080` → `--text-dim` `#8a8172`, plus `--text-brand`
`#b99a5b` for brand names and section heads, which leans gold rather than
neutral.

Four further greys existed as literals — `#9a8f79`, `#8f8574`, `#a89d8a`,
`#c9b898` — every one of them within 7 per channel of a token that already
existed. They were accidents of hand-picking, not design intent, and are folded
into the ramp.

### State — ΔE only

`--ok-*`, `--warn-*` and `--bad-*` each carry a `bg`/`border`/`text` triple.
They are reached **only** through
[`shared/lib/color.ts`](../src/shared/lib/color.ts), which maps a ΔE match
quality onto one of the three groups. No component picks a state colour
directly, which is why the same delta cannot read as "close" in one view and
"distant" in another.

`--ok-muted` `#7fa887` is separate on purpose: it is the "IN LIST" badge, which
reports a fact about the list rather than a match-quality verdict, so it stays
quieter than `--ok-text`.

### Grounds and neutrals

`--bg-page` `#050409`, `--bg-sheet` `#14111b`, `--bg-item` (white at 3.5%),
`--bg-backdrop` (near-black at 70%). The page and card grounds are image plus
gradient composites; their stops are tokenised as `--scrim-*` so both files sit
on the same near-black.

Neutral edges are `--border-subtle` (10%), `--border-faint` (8%) and
`--surface-raised` (3%).

## Type

Body is 15px EB Garamond on a 390px card. The ladder steps 1px at the small
end because at that size 11px and 12px are genuinely different roles.

| Token | Size | Used for |
| --- | --- | --- |
| `--size-xxs` | 10px | IN LIST badge |
| `--size-xs` | 11px | The workhorse label size — section heads, meta, chips |
| `--size-sm` | 12px | Secondary meta, hex codes |
| `--size-md` | 13px | List names, tab pills, primary controls |
| `--size-lg` | 14px | Paint names, prose empty states |
| `--size-xl` | 15px | Body default, set on `<body>` |
| `--size-2xl` | 16px | Sheet titles, search result names |
| `--size-3xl` | 20px | The app title |

`--glyph-sm/md/lg` (18/22/26px) size the bare `+` and `×` characters that act
as icons, so they are not mistaken for text sizes.

Tracking is the other half of the system, and the step *is* the meaning — the
wider the tracking, the smaller and more label-like the text.
`--track-sm` 0.5px → `--track-3xl` 3px, six steps.

## Radius

Nine steps, each with one job: `--radius-xs` 8px, `--radius-sm` 10px,
`--radius-md` 12px, `--radius-lg` 14px, `--radius-xl` 16px,
`--radius-pill` 20px, `--radius-sheet` 22px, `--radius-card` 30px,
`--radius-round` 50%.

`--radius-pill` is the one to reach for by default: every tab, input and
primary button uses it.

## Elevation

Six shadows, and nothing else in the app casts one.

`--shadow-card` (the desktop phone card), `--shadow-card-ring` (its gold inner
hairline), `--shadow-fab`, `--shadow-sheet-lip` (the 1px gold line along a
bottom sheet's top edge), `--shadow-swatch` and `--shadow-swatch-ring`,
`--shadow-selected-ring`.

The two swatch rings are **not** interchangeable: square swatches carry the
ring *inside* their radius (`inset`), the round colour chips carry it outside.

## Spacing — deliberately not a scale

This is the one place the extraction stopped short, on purpose.

The UI uses every value from 2px to 26px. Forcing it onto a 4px grid would mean
snapping roughly 25 values, which is a redesign, not an extraction — and it
would be a redesign performed by a rounding function rather than by anyone
looking at the screen.

So only spacing that repeats *and* carries structural meaning is tokenised:

| Token | Value | Meaning |
| --- | --- | --- |
| `--gutter` | 22px | Card side padding — header, divider, tabs, content |
| `--pad-sheet` | 20px | Bottom-sheet side padding |
| `--pad-card` | 14px | Padded surface inside the card |
| `--gap-chip` | 8px | Between pills, chips and header actions |
| `--gap-row` | 12px | Between a swatch and the text beside it |

Plus the control sizes, which are a real set: `--control-sm` 22px (inline
remove), `--control-md` 30px (header icon buttons), `--control-lg` 34px (add
button, colour chip), `--control-xl` 56px (FAB, icon tile).

And `--nav-height` 64px, which earned its name the way the rule says: three
files read it and have to agree. The bar draws it, the FAB sits above it, and
each screen's scroll padding has to clear it. It is structural in the strongest
sense — the number is not a spacing choice, it is how much of the screen is
already spoken for.

Everything else stays component-local. If a padding starts appearing in a third
file, that is the signal it has become structural and needs a name.

### Safe area — the two tokens that are not spacing

`--inset-top` and `--inset-bottom` sit in the same block but are a different
kind of thing: they are not chosen, they are *reported*, by the device, at
runtime, and they are zero everywhere else.

The web layer fills the whole screen on both platforms, so the status bar and
the home indicator are drawn on top of the app rather than beside it. Four
places spend the insets, and each spends it as padding or as an offset so the
card's background still bleeds edge to edge behind the system chrome:

| Where | What it pays for |
| --- | --- |
| `App.module.css` `.headerWrap` | The title, out from under the status bar |
| `App.module.css` `.fab` | The FAB, off the home indicator |
| `ListsPanel.module.css` `.content` | The FAB's landing zone, which rises with it |
| `Sheet.module.css` `.auto` / `.tall` | Sheet content, while the ground stays at `bottom: 0` |

Both tokens read two sources in turn — Capacitor's injected
`--safe-area-inset-*` on Android, `env(safe-area-inset-*)` on iOS — and end in
`0px` rather than `0`, because `calc()` rejects a bare zero as a length and
drops the whole declaration. The insets only report anything at all because
`index.html` says `viewport-fit=cover`; see the Native section of
[the architecture note](0.1-architecture.md).

Left and right have no tokens. Both platforms are locked to portrait, where
those insets are always zero.

At `min-width: 500px` the card is a framed 390px mock with screen edges nowhere
near it, so `.card` redefines both tokens to `0px` there. Redefining them on
the card rather than at `:root` is what keeps the media query in one place
instead of in all four consumers.

## Colours that cannot be tokens

[`src/shared/ui/listPalette.ts`](../src/shared/ui/listPalette.ts) holds the
five list banner colours as literal hex. They cannot be CSS variables: the
chosen value is **persisted into the store** and rendered later as a bare
colour, so writing `var(--gold)` to localStorage would store a string that
means nothing outside a stylesheet.

The same reasoning applies in reverse to the v0→v1 store migration, which keeps
its `#c9a86a` literal rather than importing `DEFAULT_LIST_COLOR`. A migration
has to keep writing what it wrote at the time; pointing it at a live constant
means changing the palette silently rewrites lists created years earlier.

## What the extraction changed

Not a refactor with no consequences — 19 deliberate collapses, verified by
resolving every `var()` back to a literal and diffing the computed declarations
against the previous commit:

- Four near-duplicate greys folded into the text ramp (max 7 per channel).
- Gold fill alphas 0.10/0.14 → 0.12/0.16; hairlines 0.10 → 0.15; borders
  0.30 → 0.25.
- Neutral border 0.06 → 0.08.
- `.addFirstBtn` radius 22px → 20px, joining the pill scale.
- Two rules carried `'EB Garamond', serif` where `<body>` had Georgia in the
  stack; now consistent via `--font-body`.

No other computed declaration changed. The screenshot harness could not be used
to confirm this visually — it resolves to Edge on the dev machine and fails to
launch — so the check was the computed-CSS diff, not a pixel comparison.

## Components

Tokens made the duplicates consistent; the primitives in
[`src/shared/ui/`](../src/shared/ui/) make them singular. Ten components, most
of them replacing between two and four hand-written copies.

| Component | Replaces | The decision it encodes |
| --- | --- | --- |
| `Sheet` | 43 byte-identical lines × 2 overlays | Owns Escape, the focus trap and the dialog roles *together* — they cannot be wired one-and-a-half times |
| `Pill` | `tabPill`, `filterChip`, `newTabBtn` | Always a button: every pill selects something |
| `Badge` | `inListBadge`, `equivPill` | Never interactive — the counterpart to Pill |
| `IconButton` | `iconBtn`, `iconBtnActive`, `iconBtnDanger`, `removeRight` | `label` is required; these buttons have no visible text |
| `GoldButton` | `fab`, `addBtn` | The only filled control, and only two of them |
| `GhostButton` | `addFirstBtn`, `createBtn`, `browseBtn` | The workhorse; `quiet` is an offer, not an urged action. With `href` it renders an anchor styled identically |
| `ExternalLink` | — | The inline link out of the app, and the only anchor style — there is no in-app navigation for a link to point at |
| `TextField` | `nameInput`, `searchInput`, `listNameInput` | Spreads native props — edit-in-place handling is the caller's |
| `Swatch` | `swatch`, `paintSwatch`, `equivSwatch` | Inset ring, so it reads as the paint and not as a bordered box |
| `ListIconSvg` | — | The closed 8-emblem set, on a shared 24px grid |
| `SectionHeading` | `ListsPanel`'s `.sectionType`, plus five more the Color Lab wanted | A named group is a gold Cinzel rule; the caller supplies only the words |
| `PaintSummary` | `ResultCard`'s summary row | The trailing action is a slot, because "what you can do with this paint" is the only part that differs between the surfaces showing one |

**The rule:** chrome lives in `shared/ui/`, never in a feature. A feature
stylesheet is for what is genuinely specific to that screen — a result card, a
section heading, a grid.

Two things did not become primitives, and the reasoning is the same in both
cases: they are *one* thing, not a repeated one. The emblem tile in the new-list
sheet is a square grid cell rather than a round action, so it stays local; the
colour chip is a picker with a selection ring rather than a swatch.

`BottomNav` is a third, on a different reason: it is not repeated *and cannot
be*, because it names this app's two screens rather than taking items. That
makes it shell, so it lives in `app/` and stays out of the barrel — alongside
`App` itself, for the same reason.

The Colour Lab's paint slot stayed local too, and the test was whether anything
else would ever want it. Nothing will: a slot is a hole shaped like a paint,
which is a question only the Lab asks.

What each primitive is composed of stays honest by construction — every one of
them is built from the tokens above and defines no colour of its own.
